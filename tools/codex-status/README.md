# Codex 状态灯与播报

适用板型为 `arcs_mini_v2_1`。状态通过同一局域网内的 WebSocket 传输，桥接程序运行在使用 Codex 的电脑上。板端默认关闭此功能，继续使用设备原有的配网与休眠设置。

## 1. 在 Mac 上启动桥接

在工程根目录执行。将 `192.168.1.20` 换成 Mac 的实际局域网 IPv4 地址，建议在路由器上为它保留固定地址。

```sh
python3 -m venv ~/.venvs/codex-status
~/.venvs/codex-status/bin/pip install -r tools/codex-status/requirements.txt
export CODEX_STATUS_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(24))')"
~/.venvs/codex-status/bin/python tools/codex-status/bridge.py --bind 192.168.1.20
```

保留这次生成的 token，后续启动时沿用。板端连接端口默认是 `8765`。Hook 提交事件的端口 `8766` 只在本机回环地址监听。桥接默认在终端前台运行，退出进程后板端会撤掉 Codex 灯效。连接使用明文 WebSocket，限在可信局域网内使用。

macOS 上默认的本机 TCP 8766 被占用时，桥接会改用系统分配的可用端口。助手和 Hooks 从本机运行状态文件读取实际端口。手动设置的 Hook 端口环境变量仍然优先。已配置为固定 HTTP 地址的可选 MCP 提问工具在发生端口切换时需要同步修改地址。设备启用自动发现时，默认的局域网 TCP 8765 被占用也会自动改用可用端口。新版固件会从签名发现响应读取实际端口。UDP 8767 仍为固定发现入口。

## 2. 接上 Codex Hooks

以 [hooks.example.json](hooks.example.json) 为模板，把命令里的脚本路径换成实际绝对路径。如果 Codex 的运行环境找不到 `python3`，把解释器也改为绝对路径。将这些事件条目合并到自己的 `~/.codex/hooks.json`，并在 Codex 中完成 Hook 信任检查。已有同名事件时追加处理器。

Hook 发送事件名和会话、轮次标识，结束时也会把可用的最终回复交给本机桥接。板子跟随最近一次提交任务的聊天。其他聊天的工具和结束事件不会覆盖这个聊天的状态。Windows 可以复用 Python 桥接和板端协议，Hook 路径、启动方式和防火墙需要在 Windows 上验证。

### 待确认提醒

`PermissionRequest` 会让办公模式显示紫灯双闪。板端优先使用当前绑定的灵心智能体朗读审批原因，用户在桌面查看并处理具体操作。说明缺失时播报操作类别，智能体无法播放时可回退到 Mac 合成音频或板载提示音。相应的 `PostToolUse` 或本轮下一次 `PreModelRequest` 恢复执行状态，结束或中断时退出紫灯。板子通过能力声明协商普通状态、音频标识或带文本的审批帧。桌面的结构化选项卡片需要由持有原请求的客户端处理。

## 3. 编译并联调板端

在工程外或忽略目录里创建配置覆盖文件（如 `/tmp/codex-status.conf`）。填入与桥接相同的地址和 token。

```ini
CONFIG_APP_CODEX_STATUS=y
CONFIG_APP_CODEX_STATUS_HOST="192.168.1.20"
CONFIG_APP_CODEX_STATUS_PORT="8765"
CONFIG_APP_CODEX_STATUS_TOKEN="填入上一步生成的 token"
```

```sh
bash ./build.sh -S apps/arcs-mini -B build-aec-software \
  -DBOARD=arcs_mini_v2_1 '-DCONFIG_FILES=aec-software.conf;/tmp/codex-status.conf'
```

确认实物板型后，按项目的 ADB 流程更新本次的 CP app 与 tone 分区。固定审批提示和回复回退音由本地 MP3 资源提供，构建会自动打包。板子连上与 Mac 同一局域网的 Wi-Fi 后，提交一条 Codex 消息验证蓝色呼吸，等回复时验证青色短闪和语音。审批测试应选择实际会触发审批的工具和权限配置。

配网、低电量、OTA 和现有交互灯效优先。语音提醒在播放器和设备空闲时播放，本轮结束播报最多等待 10 秒。设备进入原有语音待机并关闭 Wi-Fi 后，唤醒恢复联网时会重新同步；已错过的提醒不会补播。验证时也应检查语音通话、配网、断网重连和剩余堆内存。

## 协议

设备连接 `/status/<token>`，桥接发送简短的 WebSocket 文本帧。连接时发送 `1 S <state>` 同步当前状态，之后发送 `1 E <state>` 表示一次状态变化。状态为 `idle`、`working`、`approval`、`done`。同步帧只更新灯效，`done` 只随事件发送。

## 动态播报

Mac 在后台用系统语音合成朗读回复。短答直接朗读，长答去除代码块和链接后取开头一到两句，最长 120 字。回复文本只发送到电脑本机的桥接，板子收到的是短时音频标识。音频在内存中保留一条，30 秒后地址失效。Wi-Fi 链路上的 MP3 使用普通 HTTP，适用于可信局域网。

有动态播放能力的板子连接 `/status/<token>/audio`。桥接可以发送 `1 E done <clip-id>`，由板子从同一主机的 `/audio/<clip-id>.mp3` 播放。普通的 `1 E done` 仍触发固定回复音。回复缺失、合成失败或在 Windows 上运行桥接时，会使用固定回复音。板子重连只同步当前状态。

## 回复结束动作（可选）

在板端配置覆盖文件中加入 `CONFIG_APP_CODEX_STATUS_DONE_MOTION=y`，使用一次原地轻蹲再站起作为回复结束反馈。每轮最多尝试一次，动作完成或被拦下后再播报，其他音频仍优先。设备需已站稳且动作系统空闲；USB 供电、OTA 等现有后台动作限制同样适用。唤醒或前台语音接管时，后台动作沿用原有中断和安全回位流程。重连只同步状态。

## 使用板子当前绑定的智能体（试用）

试用固件配置 `CONFIG_APP_CODEX_STATUS_AGENT_VOICE=y`，桥接启动时加 `--agent-voice`。板子在对话和播放器空闲时，用已有灵心绑定生成一句任务简报。桥接保留回复开头和结尾的关键信息，智能体按实际结果概括进展和下一步。合成未启动时回退到固定提示音。回复结束时先尝试原地轻蹲再站起，再请求灵心播报。Codex 的灵心播报会预缓冲约 0.77 秒音频，短句在收到完整音频时直接播放。取消桥接的 `--agent-voice` 即可切回 Mac 音色，无需重新刷板。

执行持续超过 5 秒时，设备空闲才会尝试播一次「任务正在执行，请稍等」。短轮次、重连快照和审批返回执行状态时不补播。最终简报会按回复中明确的失败或阻塞说明原因，中途工具报错不单独播报。

## 办公模式与娱乐模式

每次开机都从娱乐模式开始。四击主按键立即切换，蓝灯短闪表示办公模式，绿灯短闪表示娱乐模式。设备结束旧模式的当前小聆对话，等播放器空闲后播放本地确认音。进入办公模式时会暂缓尚待确认的 OTA 更新。娱乐模式暂停 Codex 的灯光、播报和动作。切入办公模式后立即接管当前执行或审批状态，已经结束的任务不会补播。

### 办公模式语音输入

开启 `CONFIG_APP_CODEX_VOICE_INPUT=y`，并在固件配置中以 `CONFIG_APP_CODEX_VOICE_KEY` 设置一个独立的 32 字节十六进制密钥。将同一密钥放在 Mac 的私有文件中。启动桥接时加上 `--agent-voice --voice-key-file <密钥文件> --whisper <whisper-cli 路径> --whisper-model <中文兼容的模型路径>`。如 Codex 不在服务的 PATH 中，用 `--codex` 指定路径。关闭该固件开关即可恢复两个模式的原始唤醒行为。

办公模式下，说「小聆小聆」，听到「请说下一步任务」后说一句指令。录音最长六秒，提交到最近完成且仍对应当前桥接状态的 Codex 会话。Mac 默认使用 SenseVoiceSmall 在本机转写并通过 `codex queue` 投递，原会话进程在空闲时消费队列。设备的「指令已排队」表示已进入队列。娱乐模式的唤醒和普通单击照旧。

录音只在这次唤醒后采集，Mac 的临时文件在识别完成后删除。设备和桥接用独立密钥校验录音，Wi-Fi 传输仍是明文，因此只适用于可信局域网。换会话、断线、播放中或识别失败时，用户可重新发起一次。

办公唤醒的录音提示和提交回执优先使用板子当前绑定的灵心智能体音色。两句固定录音提示首次完整播放后在板端内存缓存 15 分钟，再次唤醒可直接播放；重启后重新生成。提示播完后才打开办公录音，灵心暂时不可用时使用板载提示音。

### 用设备回答选项

在本机 Codex 执行 `codex mcp add ls26 --url http://127.0.0.1:8766/mcp`，随后让桌面客户端重新加载 MCP。可以在任务里说「遇到需要我选的低风险方案，用 LS26 的 ask_choice 问我」。工具一次问一个简短问题，提供两到三个选项。等板子播报完毕，用「小聆小聆」唤醒，听到「请说选第几项」后回答「选第一项」等。

桥接最多等 45 秒，将结果返回发起提问的工具调用。切换任务、退出办公模式、断线或出现操作审批时，会取消尚未回答的问题。操作审批仍在桌面处理。

## Mac 菜单栏助手（联调版）

当前 Apple 芯片发行包以 macOS 13.0 为最低构建目标。Swift 助手使用显式部署目标。打包用的 Whisper 应用同一部署目标构建，并关闭会引用 macOS 13.3 新接口的 BLAS 加速路径（`GGML_BLAS=OFF`、`GGML_ACCELERATE=OFF`）。Python 运行时和二进制依赖应与目标架构匹配。旧系统实机验收后再公布支持范围。Intel Mac 需要单独构建与验收。


```sh
bash tools/codex-status/macos/build.sh /tmp/ls26-assistant
open "/tmp/ls26-assistant/摩突突助手.app"
```

菜单栏助手使用本机桥接的 `/setup` 查看连接和设备模式。菜单可切换办公模式和娱乐模式，收到设备回执后显示结果。点「测试设备灯光与声音」后，设备接收测试请求，亮青灯并尝试播放板载网络连接成功音。打开助手会检查并启动已配置的 macOS 桥接后台服务。桥接离线时也可从菜单点「启动桥接」。带发布配置的 DMG 首次打开会自动准备桥接。设备配网后，同一局域网内的一台摩突突设备可自动连接。请在 Codex 打开或新建一个本地项目，再从「设置 → Hooks」审查并信任新增条目。没有打开本地项目时，桌面端可能显示「未找到钩子」。构建安装包时，`MOTUTU_DEVICE_PROFILE` 指向发布配置 JSON。其状态与语音字段应和该批次固件构建配置一致。现有手动配置版可继续使用导入入口。

新 Mac 可在菜单点击「导入设备配对文件」。带内置运行时的安装包会在本机安装随包提供的 Python 和桥接依赖，合并 Hooks 并注册后台桥接。开发者可在构建时把 `MOTUTU_BUILD_PYTHON` 指向与目标架构匹配的可搬移 Python。未打包运行时的开发版仍需要系统可运行的 Python 3 和联网安装依赖。打开 Codex 后仍需信任新增的 Hooks。

配对文件由设备交付方单独提供，使用 JSON 对象。字段 `status_token` 对应固件状态密钥，`voice_key` 为可选字段，对应固件的 64 位十六进制语音校验密钥。交付方应为不同设备分别分配密钥，并通过私有渠道交付配对文件。设备保持现有 Wi-Fi 配网流程。语音续办需要配对文件提供语音密钥。当前发行包内置 SenseVoiceSmall 及其离线运行库。首次配置时自动安装，已通过助手安装桥接的 Mac 会在打开新版时迁移。桥接会寻找已安装的 Codex。请先安装 Codex，再配置助手。开发者可用 `MOTUTU_SENSEVOICE_ASSETS` 指定包含 `model.int8.onnx`、`tokens.txt`、`LICENSE` 和目标架构 Python 依赖目录 `deps` 的资源目录。若仍需打包 Whisper 开发版，可通过 `MOTUTU_WHISPER_ASSETS` 指定包含 `whisper-cli`、`ggml-small.bin` 和 `LICENSE` 的目录。

要验证自动重连，在固件覆盖配置中启用 `CONFIG_APP_CODEX_STATUS_DISCOVERY=y`，将 `CONFIG_APP_CODEX_STATUS_HOST` 留空。桥接在可信局域网用 `--bind 0.0.0.0 --discover` 启动。设备通过 UDP 8767 发出带随机数的发现请求，校验电脑返回的地址、端口和签名，再连接实际 WebSocket 端口。旧桥接和旧固件仍支持只发现地址的协议，使用双方预先配置的同一端口。板端和桥接的状态密钥必须一致。网络需要允许局域网广播和设备到电脑的 TCP 连接。
