# ARCS Motion Studio

ARCS Motion Studio 是 `arcs_mini_v2_1` 无屏板的四足动作编排上位机。它控制
PA04～PA07 上的四路 50 Hz PWM 舵机，固定通道顺序为
`CH0/PA04=FL` 左前、`CH1/PA05=FR` 右前、`CH2/PA06=RR` 右后、
`CH3/PA07=RL` 左后；PA08 连接 WS2812 灯串。姿态和
灯光保存到同一条动作时间线。

## 启动

要求 Python 3.10 或更高版本、Android Platform-Tools，以及一条可传数据的
Type-C 连接。Linux/macOS 执行：

```bash
bash tools/启动四足运动台.sh
```

Windows 双击 `tools/启动四足运动台.bat`。只有一块板在线时会自动选择；多板
同时在线时先运行 `ADB_LIBUSB=0 adb devices -l`，再指定本次会话的 transport ID：

```bash
bash tools/启动四足运动台.sh --transport 12
```

服务默认只监听 `127.0.0.1`，不会向局域网开放控制接口。
启动器还会把工程自动保存到 `tmp/quadruped-motion-project.json`。

## 推荐的动作制作流程

1. 点“新建动作”，选择自定义、前进、后退、原地踏步、左转或右转。
2. 步态模板先使用默认的四拍慢走、10% 行程和 0.30 Hz；它会生成一组可编辑
   的组合关键帧。翻跟头因当前 4×1DOF 机构与重心条件未验证，入口保持禁用。
3. 先点“3D 安全预览”。预览只驱动页面模型，即使设备在线、舵机已解锁也不会
   发送 `/api/pose`。
4. 单击时间线中的编号姿态点加载它，调四腿和灯光后点“更新当前姿态”；需要
   保留原姿态时点“另存为新姿态”。拖动编号可以改变关键帧时间。
5. 架空机器、完成校准和供电预检后，先解锁并用“试当前帧”逐帧慢速验证。
6. 每帧方向和机械余量都确认后，才用“真机播放”从低倍速验证连续动作。

实时录制是另一条入口：输入动作名称，点“开始录制”，拖动四路舵机或调灯光，
最后点“停止并保存”。变化会按时间戳写入同一个组合姿态轨道。

页面和主机会自动保存；要换电脑、发给别人或长期归档时，点“下载备份”
生成 `.arcsmotion.json` 文件。

## 首次三步标定

标定会按设备真实 `chip_id` 分开保存。断线、换板或 ADB 连接世代变化后，
旧记录会立即失效；当前板没有记录时，后端强制使用 1000～2000 µs 保守限位。

1. **舵机机械基准**：先架空机身并清场，逐路确认 center、方向、min/max
   和 trim。需要观察真机时可人工解锁；保存前必须重新锁定。
2. **Home / 站立姿态**：使用已保存的舵机标定调好当前姿态，锁定后捕获
   四路精确 `home_pose_us`。预览不驱动真机，也不会默默回退到 1500 µs。
3. **IMU 水平基准**：把机身放在水平面上静置至少 3 秒。向导会检查唯一新样本、
   重力幅值、振动、角速率与 Roll/Pitch 方差；只持久化传感器坐标下的 Roll/Pitch 水平
   基准。显示时当前样本与基准会各自经过同一板型安装变换，不会重复补偿。
   MPU6050 没有磁力计，Yaw 只能在每次会话中单独归零。

解锁只会取得控制权并启动安全租约，**不会自动下发页面当前姿态**。
通道名是 V2.1 实机线序，不是可自由重排的解剖顺序：所有标定、Home、
关键帧和板端命令数组都必须保持 `FL, FR, RR, RL`。反向属于单机标定，
必须逐路确认并保存到当前 `chip_id` 的记录，不可因一台样机的现场结果
改成全局默认。

## 四腿同步起身 / 趴下

“同步起身”和“同步趴下”是两个锁定态专用操作，不是通用时间线播放。
页面将 `FL, FR, RR, RL` 四个目标作为一个 identity-bound
`POST /api/posture-test` 请求交给后端；后端只发一条
`v2hw servo frame ...` 命令，因此四路从同一板端帧开始平滑过渡，不再按腿轮流。

执行前必须保持 `OUTPUT LOCKED`、设备身份有效、VBAT 预检通过，且播放和
录制都已停止。当前过渡为 800 ms；后端在下发前先全关，启动有限时间的
板端看门狗，过渡结束后再全关并复读 `enabled_mask=0` / `active=false` /
`watchdog_ms=0`。急停会先取消姿态事务，避免安全断开后又被迟到帧重新打开 PWM。

起身目标始终读取当前设备已保存的 Home。趴下目标必须同时匹配 `chip_id`、
board、mounting revision、精确 Home 和四路舵机标定签名；当前样机
`6b3bc01b1642ccbd` 的 Home 是 `2100 / 900 / 2050 / 870 us`，已验证趴姿是
`1750 / 1250 / 1750 / 1250 us`。两组值都作为整机实测数据绑定，不能再从
旧的对称 Home 或中点公式推导。首试仍要先站稳、扶住机身并保持急停可触达。
其他芯片没有自己的整机趴姿记录时，“同步趴下”会直接拒绝。即使是同一芯片，
重新装腿、改 Home、改反向/软限位后也必须重新标定。

## 3D 预演与 IMU 实机姿态

中央的 3D 狗模型会随四路目标角度动画，并反映当前灯色。它是一腿一自由度的
可视化参考，不是机构位置反馈。模型为 C. Yamahata 的“Robot dog Unitree Go1”，
依 CC BY 4.0 使用，本项目对材质、布光和骨骼映射做了可视化适配。

设备在线时，后端以最高 10 Hz 执行只读命令 `v2hw mpu`，把 MPU6050 原始值、
换算后的加速度/角速度及融合姿态以 **MPU6050 传感器坐标**原样缓存到
`GET /api/imu`；后端 raw/scaled/attitude 不做安装补偿，便于追溯。浏览器再按实时连接板型
选择固定的 sensor→body 安装变换；`arcs_mini_v2_1` 默认为绕 X 轴 180°（向量映射
`x, -y, -z`）。因此主板朝上且机身水平时，即使 raw `az<0` / raw Roll≈±180°，机身 Roll
仍接近 0°。该机身姿态是 Roll/Pitch 读数、3D 模型与浏览器倾倒保护的唯一共用输入。
数据过期时保留最后姿态并标记 STALE，不会伪装成实时数据。

10 Hz 采样与页面刷新共用唯一持久 ADB shell；舵机、急停或其他设备命令正在占用传输时，
IMU worker 会直接跳过当前时隙而不排队，因此姿态预览不会阻塞动作或安全命令。

- Roll/Pitch 使用加速度计与陀螺仪互补滤波；动态加速度过大时暂不信任重力方向。
- Yaw 没有磁力计绝对参考，是启动/滤波复位后的相对角度，长期运行会漂移。为避免机器人静置时
  3D 模型持续转向，模型默认锁定航向、只跟随 Roll / Pitch；仅在操作者主动开启
  “3D 航向跟随”后才把相对 Yaw 送入模型。该开关只影响 3D 可视化，不改动姿态读数、
  Yaw 会话归零或倾倒保护。
- “Yaw 会话归零”只在当前上位机会话中建立航向零点，不写入设备。
- 固定安装变换只解决传感器轴与机身轴的机构关系；三步向导保存的水平基准只消除单机
  小偏差。IMU 反映机身运动，不代表舵机、关节或足端位置反馈。

## 安全边界

- 页面和后端每次启动都处于锁定、急停状态，打开页面不会输出舵机 PWM。
- 解锁前会读取 `v2hw power`。舵机接口 pin 2 使用 VBAT；未检测到可用电压时
  默认拒绝解锁。独立外部电源必须稳压、与主板共地，并通过显式确认覆盖预检。
- 每路默认软限位仍为 1000～2000 µs、中位 1500 µs。先架空四腿，再逐路校准
  min/center/max、方向和 trim；单点与动作帧的固件电气硬边界为 500～2500 µs。
- `v2hw servo sweep` 是端点扫描工具，同样限定为 500～2500 µs。扫描前必须架空机身并确认机械行程。
- 解锁后板端控制租约持续监视主机心跳。页面关闭、ADB 断开、命令超时或租约
  到期都会关闭四路 PWM；Esc 和页面顶部红色按钮会立即急停。
- 可选“倾倒保护”只在浏览器、主机、ADB 和应用均存活且 IMU 数据新鲜时请求急停，
  默认关闭；它不是独立硬件断电保护，不能代替机械限位、保险丝或舵机电源开关。
- 常规 PWM 舵机没有位置传感器。页面中的角度是校准后的目标映射，“已确认”
  只代表固件收到了命令，不代表机构真的到达该角度。
- 四路接口是一腿一自由度。内置慢速步态只提供小幅相位示例，能否真正行走取决
  于舵机安装方向、连杆、重心和供电能力，不能替代机构标定。
- 灯串默认低亮度。灯珠数量和满白电流近似线性增长；未确认灯板供电预算前，
  不要使用 64 颗、100% 亮度的满白输出。
- V2.1 上位机和固件默认按 8 颗发送；若实物数量不同，以页面“灯珠数”为准。
  若页面与设备状态已经确认 `count=8` 而仍只亮第一颗，PA08、首颗 DIN 和首颗
  发光通路已经工作，下一步应断电检查首颗 DO → 第二颗 DIN、级联方向、后续
  灯珠 VBAT/GND；这时重复刷机不能修复灯板级联开路。

## 功能

- 四腿按物理通道 FL/FR/RR/RL 实时滑条，目标角度与 PWM 脉宽双显示；
- 每路安全行程、中位、反向和 trim 校准；
- 0～10 秒过渡时长，以及 Linear、Smooth、Ease In、Ease Out 缓动；
- 灯光开关、颜色、亮度和 1～64 颗 uniform fill；
- 组合姿态时间线、覆盖更新/另存/复制/删除、录制、循环和 0.25～2 倍播放；
- 自定义、前进、后退、踏步和左右转步态生成器，支持腿序、行程、频率、周期和
  转向混合；
- 与真机控制完全分离的 3D 安全预演和时间线拖动预览；
- MPU6050 原始/换算数据、相对姿态、会话归零、陈旧状态和可选主机倾倒保护；
- 工程 JSON 导入/导出和浏览器本地自动恢复；
- Space 开始/停止 3D 安全预演、R 录制、Esc 急停、Home 回中；
- ADB transport、命令延迟、VBAT、控制租约和固件状态显示。

“速度”不是修改 PWM 的 50 Hz 载波，而是调整从当前脉宽到目标脉宽的过渡时间。
实际速度仍受舵机型号、负载、电压和机械摩擦限制。

### 真机单关键帧测试

时间线的“试上一帧 / 试当前帧 / 试下一帧”只下发一个已保存的四路组合姿态，
用于先确认运动方向、碰撞和机械余量。它要求设备在线、舵机已解锁、播放和录制
均已停止；即使关键帧原本是 Step 或几十毫秒的动态帧，单步也会强制使用平滑曲线，
并按播放倍速放慢到至少 1000 ms。这个操作不会另发一条灯光命令，避免同一帧被拆成
两个独立设备事务。

“命令已确认”只表示板端收到目标。普通 PWM 舵机没有位置反馈，单步结果仍需现场
目视确认。单步慢速测试也不能证明动作具有足够的起跳动量；它只负责排除方向反了、
连杆顶死和目标越界等低速问题。

### 翻跟头 / 地面翻滚实验流程

四条腿各一自由度并不等于理论上绝对不能翻。Flexipod 论文展示了 4×1DOF 四足通过
前后腿高速旋转和时间偏移完成后空翻，但该平台使用 3 N·m、469 rpm 的反馈电机、
6S 高倍率电池和可储能/吸收落地冲击的软体腿壳，不能把它的时序直接套到本机普通
位置 PWM 舵机上。MIT Mini Cheetah 的空中动作研究也表明，关键是接触起跳阶段在
离地瞬间同时建立足够的质心竖直速度和俯仰角速度，而不是几张静态姿态图。

- Flexipod：<https://arxiv.org/abs/2011.06749>
- MIT 动态空中动作：<https://arxiv.org/abs/2110.06330>
- 小龟 B4 官方挑战页：<https://xiaogui-robot.com/erha2/>
- 小龟 B4“连翻与重力”：<https://www.bilibili.com/video/BV1Me411m7W4/>
- Petoi Bittle 官方后翻动作表：
  <https://github.com/PetoiCamp/OpenCat-Quadruped-Robot/blob/main/src/InstinctBittle.h#L441-L449>
- QRoSS 小输出执行器借外壳接触滚动：
  <https://link.springer.com/article/10.1186/s40648-020-00170-5>

本机先以“能越过机身完成一次受控地面翻滚”为阶段目标，不先承诺腾空后四脚落地。
最接近本机结构的小龟 B4 官方演示表明，它的“连翻”不是靠一个静态目标，而是前掌/
外壳持续接触地面的分段滚动；机身翻面后还依据姿态传感器改变动作与四条腿的对应关系。
Petoi Bittle 的开源后翻同样是一个带逐帧速度和延时的本地行为。本机采用双面四足策略，
目标是前滚 180° 后把四腿镜像到机身另一面站立，不再继续滚到 360°：

1. `预压`：从 HOME `2100 / 900 / 2050 / 950 us` 进入已验证趴姿
   `1750 / 1250 / 1750 / 1250 us`，降低重心并给后腿留出行程。
2. `后腿冲量`：前腿保持趴姿，后腿 `RR / RL` 同步快速到 `2050 / 950 us`；目标是
   朝头部压到前壳接地，不是腾空。1000 ms 平滑变化只会静态翘臀。
3. `翻到背面`：越过前壳平衡点后落在粉色上盖；IMU 确认倒置并等待冲击结束。实机照片
   已确认该上盖是稳定平面，四只脚此时均悬空。
4. `四腿同步换面`：保持物理通道顺序不变，以 `1500 us` 为中心执行
   `p_inv = 3000 - p`。候选倒置趴姿为 `1250 / 1750 / 1250 / 1750 us`，候选倒置
   Home 为 `900 / 2100 / 950 / 2050 us`；必须从每路 200 us 的增量慢测开始。
5. `倒置站立`：四腿全部到另一面且 IMU 仍确认倒置后，才进入倒置 Home。后续若需要
   倒置行走，还要交换前后腿的控制语义；静态站立阶段不交换通道数组。

当前样机的慢速 B 方向梯已经实机确认：前腿从趴姿回到支撑、后腿保持趴姿时，机头会
明显抬起。`软垫后滚 B2 · 400ms 临界点（仅 1×）` 又让前端抬得更高，但没有越过
后壳支点；播放完成后按预期断开了 PWM。由于本机 USB 插头和线缆位于后滚路径，当前
不再增加 B 的后腿幅度，改为朝头部/两颗黑色圆件一侧前滚。

切换方向后先使用 `翻滚调试 A · 朝头部前滚慢测`：HOME → 趴姿 →
`1750 / 1250 / 2050 / 950 us` → 趴姿 → HOME。实机已经确认第三段会让屁股抬高并
朝机头压，方向正确；最后又站起是动作表含恢复帧，不代表已经产生翻转动量。

PWM 关闭的人工慢滚已经确认：麦克风塞入壳体后，白色/粉色壳体先接地；越过前棱后会
落稳在粉色上盖，不需要寻找“远侧接触腿”。`倒置换面慢测 · 四腿同步分级（只逐帧）`
用于验证第 4 段。第一轮只测试 `1900 / 1100 / 1850 / 1150 us`，平滑 1500 ms 后
断 PWM；只有四腿都朝另一面同向移动且无碰壳、卡滞、嗡叫，才继续后续帧。禁止完整播放。
所有动态测试仍必须移到地面厚垫，USB 从后上方留大松环，周围硬物清空，不开循环。

最终动态动作必须作为一个连续的本地关键帧序列播放，不能依靠云端逐段下发；网络和
大模型延迟会破坏起跳时序。开始压缩第 2～5 段前，必须补齐舵机型号/额定电压、空载
速度、堵转扭矩、整机质量、重心和腿部可用角度，并观察四舵机同时动作时的 VBAT 压降。

## 板端协议

上位机只使用一个持久 ADB shell，并合并快速拖动产生的过期目标。主要命令为：
主机会在建立该长连接之前，先用一次 transport-bound 短命令读取 `chip_id`；
短命令完全退出后才打开唯一长连接。设备端只允许一个 shell，因此在长连接存活期间
不得再另开 `adb shell` 进行身份识别。

```text
v2hw servo frame <duration_ms> <easing> <us0> <us1> <us2> <us3>
v2hw servo state
v2hw servo stop
v2hw servo all-off
v2hw servo watchdog <0|200..5000>
v2hw rgb strip <count> <r> <g> <b> <brightness_percent>
v2hw rgb release
v2hw motion frame <duration_ms> <easing> <us0> <us1> <us2> <us3> <count> <r> <g> <b> <brightness_percent>
v2hw mpu
```

固件以 20 ms 为周期对四路脉宽插值，并使用一次 GPT shadow load 同步更新通道
4～7。`servo state` 和有效动作命令会刷新控制租约；不需要单独的 kick 命令。动作
播放期间灯光由 ACTION/MANUAL owner 持有，避免配网或 NFC 状态灯覆盖；急停或退出
时释放 owner。`motion frame` 将四路舵机目标和灯光状态作为同一个时间线关键帧下发。

## 工程文件

导出的 JSON 使用带版本号的 `arcs-motion-project` schema，保存设备校准、动作、
关键帧、过渡、缓动和灯光。导入时所有 ID、数组长度、时间、脉宽、颜色、灯珠数

## 首次带载验收

1. 不装连杆或架空机构，确认四路信号、VBAT 和共地。
2. 保持页面锁定，逐路把舵机机械臂安装在中位。
3. 以 1000～2000 µs、至少 1000 ms 过渡逐路校准，确认没有顶死。
4. 测试急停、拔 Type-C 和关闭页面，确认 PWM 均会在租约窗口内关闭。
5. 再测试四路同步小幅动作，观察 VBAT 压降和主板是否复位。
6. 最后连接灯板，从一颗、低亮度开始确认 GRB 色序和供电温升。
